# Развёртывание и откат

## Репетиция на копии PostgreSQL

1. Сохраните дамп через прямое подключение PostgreSQL. Используйте закрытое хранилище.
2. Восстановите дамп в чистую тестовую базу или создайте отдельную ветку Neon. Укажите тестовую базу в `DATABASE_URL` и `DATABASE_URL_DIRECT`.
3. Запустите `python -m app.preflight --dry-run`, затем `alembic upgrade head` и `alembic check`. Dry-run возвращает код 2, если найдены несовместимые строки, и указывает номера строк в порядке ID. Проверяйте оригинал и исправленную копию данных отдельно. Пустые жанры представляются как `[]` в старых JSON-архивах, числовые строки в поддерживаемых полях v1 преобразуются в числа. Неизвестный статус, повреждённый JSON и некорректный прогресс требуют решения владельца данных.
4. На тестовой базе сверьте число записей, ID, события и прогресс. Проверьте создание резервной копии, предпросмотр, восстановление и повторный экспорт.

```sh
pg_dump --format=custom --file=watch-tracker-before.dump
pg_restore --exit-on-error --single-transaction --no-owner --no-privileges watch-tracker-before.dump
```

Для каждой команды укажите соответствующий DSN или параметры PostgreSQL через переменные окружения. Восстанавливайте дамп только в заранее выбранную чистую базу.

## Render и Railway

Существующий сервис использует Render. Выставьте `APP_ENV=production`, точный HTTPS-origin в `APP_ORIGIN`, сильный случайный `APP_TOKEN` длиной от 32 символов и URL действующей PostgreSQL-базы. Если рантайм подключается через пулер, `DATABASE_URL_DIRECT` должен указывать на ту же базу и ветку через прямой адрес. Render и Railway требуют PostgreSQL в штатном окружении.

Для Render Python используйте `pip install -r requirements.txt`, Python 3.12 и `uvicorn app.main:app --host 0.0.0.0 --port $PORT --no-access-log`. Для Docker используйте команду образа, а для Railway конфигурацию `railway.toml`. Health check использует `/api/health`. На платном Render применяйте миграции через pre-deploy. На бесплатном Render выполняйте `alembic upgrade head` отдельно перед переключением версии. [Render Deploys](https://render.com/docs/deploys)

`FORWARDED_ALLOW_IPS` передаётся Uvicorn через окружение во всех вариантах запуска. По умолчанию он доверяет loopback. Перед настройкой дополнительных адресов подтвердите непосредственный адрес прокси, закрытый доступ к внутреннему порту и очистку входящих forwarded-заголовков на границе. Вводите только адреса или проверенные сети непосредственных прокси. Без дополнительного доверия попытки с нескольких адресов могут делить одну квоту, если приложение видит общий прокси. Правильный ключ сохраняет доступ даже при исчерпании квоты ошибочных попыток.  [Параметры Uvicorn](https://www.uvicorn.org/settings/#http)

## Переключение и откат

1. Назначьте окно обслуживания, остановите старую версию и другие процессы записи, затем снимите финальный дамп. До окончания репетиции сохраните отключённое автоматическое переключение production.
2. Примените миграции и запустите новый образ или сервис. При старте приложение сравнивает ревизии БД с heads Alembic и проверяет обязательные строки блокировок. Проверьте health check, вход, число записей и экспорт.
3. Для отката остановите запись и сохраните снимок текущего состояния. Восстановите предмиграционный дамп в отдельную базу, проверьте её и переключите прежнюю версию на неё. Данные после переключения сверяйте отдельно до переноса в восстановленную базу.
4. PWA вычисляет версию по содержимому при старте процесса. Развёртывание прежней сборки возвращает её прежние URL статических ресурсов. Вкладка со старым воркером может пройти обычный цикл активации при откате.

Серверные резервные копии восстанавливаются по ID и требуют нового предпросмотра после другой записи в коллекцию. Для больших доверенных файлов используйте `python import_data.py watchlist.json --large-archive --preview` и только после проверки тот же вызов с `--mode replace --confirm-replace` вместо `--preview`. CLI загружает JSON в память, поэтому выделите память исходя из размера файла. Ручные копии сохраняются до явного удаления. По умолчанию из автоматических копий сохраняются последние 20 за 30 дней и как минимум одна самая свежая.
