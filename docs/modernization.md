# Отчёт о модернизации Watch Tracker

Исходная ветка `main`, коммит `30e38bf1248f77bf3ea275e10bd6c6fb2427c78f`. Изменения подготовлены в локальной ветке `modernization`. Production-база и настройки Render и Neon не менялись. [Исходный коммит](https://github.com/remodik/watch-tracker-app/commit/30e38bf1248f77bf3ea275e10bd6c6fb2427c78f)

## 1. Аудит исходного приложения

Исходный сервер содержал одну модель `items` и API для чтения, создания, изменения, удаления и массового импорта. SQLite и PostgreSQL использовали одну схему, создаваемую при импорте модуля. Один HTML-файл содержал интерфейс, CSS, редактирование, фильтры по жанру и статусу, поиск и клиентский экспорт JSON. Отдельный скрипт импортировал прежний массив `watchlist.json`. Реализация модели и обеих веток импорта проверена по исходникам.

| Приоритет | Исходная проблема | Состояние после изменений |
| --- | --- | --- |
| Критический | При пустом `APP_TOKEN` API открывал чтение и запись. Токен вводился через `prompt()` и сохранялся в браузере. | Отсутствие секрета останавливает запуск в production. Вход использует серверную сессию, cookie и CSRF. Старое поле `localStorage` удаляется в браузере. |
| Критический | Режим замены фиксировал удаление таблицы до записи нового набора. | Снимок, удаление и импорт выполняются в одной транзакции. Откат проверен с принудительной ошибкой записи после удаления. |
| Высокий | Значения `type`, `status` и `id` подставлялись в динамический HTML и inline-обработчики. | Интерфейс строит DOM явно. Тексты вставляются как текст, ссылки для изображений проходят проверку HTTPS, события привязываются через DOM API. Добавлены CSP и заголовки безопасности. |
| Высокий | Старые зависимости разрешались с уязвимой Starlette. | `pip-audit` сообщил об уязвимостях исходного набора. Повторный аудит закреплённых зависимостей не показал известных уязвимостей. |
| Средний | Дубликаты сравнивались после загрузки всей коллекции и только по названию. | Поиск совпадений использует индексы, тип, год, нормализованное название и ID каталога. Уникальность и транзакционная блокировка защищают от гонок. |
| Средний | Старый API принимал произвольные типы и статусы и несовместимые значения прогресса. | Входные схемы ограничивают типы, диапазоны, длины, URL, даты, массивы и размер тела запроса. Ошибки логина не возвращают отправленный секрет. |

## 2. Реализованные изменения

- **Безопасность и целостность.** Отзываемые 30-дневные сессии, выход и завершение всех сессий, ограничение попыток входа в базе, `compare_digest`, CSRF, атомарные импорт и откат, автоматические резервные копии. При редактировании проверяется версия записи, чтобы старая форма не перезаписала прогресс, изменённый в другой вкладке.
- **Архитектура и схема.** FastAPI разделён на конфигурацию, зависимости, модели, схемы, маршруты и сервисы. Alembic перенимает исходную таблицу, добавляет отпечатки идентичности, поисковые поля, отслеживание, метаданные и индексы. Добавлены таблицы `watch_events`, `backups`, `auth_sessions`, `login_failures` и таблицы блокировок. Сохранены старые поля и идентификаторы, для новых записей используются UUID.
- **Интерфейс.** Cinematic Dark, локальные Manrope и Onest, Lucide, боковая панель со сворачиванием, отдельная мобильная навигация, компактный баннер, обзор и три вида медиатеки. Поиск отменяет устаревшие запросы, фильтры и сортировка отражаются в URL. Страница произведения объединяет метаданные, действия, прогресс и журнал. Настройки управляют видом, экспортом, импортом, резервными копиями и сессией.
- **Каталоги.** Реальные вызовы AniList GraphQL и TMDB по HTTPS с тайм-аутом, ограничением параллелизма, коротким кешем, повтором временных ошибок и обработкой `429`. TMDB локализует названия и содержит атрибуцию в настройках. Ручной режим работает при отключённых и недоступных интеграциях. [Условия AniList](https://docs.anilist.co/guide/terms-of-use) · [Атрибуция TMDB](https://developer.themoviedb.org/docs/faq)
- **Отслеживание и статистика.** Шесть статусов, отметки отдельных эпизодов и сезонов, повторные просмотры, оценки, избранное, даты, реальные события истории. Месячные графики и годовой отчёт используют зарегистрированные события. Для подтверждённых эпизодов доступны список и календарь в часовом поясе браузера. Время обозначено как оценка.
- **PWA и качество.** Manifest, иконки, maskable-иконка, офлайн-страница, уведомление об обновлении и кеш только статических ресурсов. GitHub Actions описывает проверки Python, форматирования фронтенда, миграций на PostgreSQL 16 и сценариев Chromium.

Тест с 2 500 синтетическими записями подтвердил, что первый экран медиатеки строит 36 карточек. В одном локальном прогоне через SQLite-контейнер медиана чтения страницы составила около 22 мс, медианы обзора и статистики — около 236 мс. Холодное открытие медиатеки на ширине 390 px с четырёхкратным замедлением CPU в Chromium заняло около 3,4 с. Эти замеры характеризуют тестовую среду.

## 4. Частично проверено и ограничения

- Миграции и восстановление проверены на изолированных копиях исходной схемы. Перед переключением production повторите проверку на копии фактических данных Neon. На время переключения остановите старых писателей, которые не обновляют новые служебные поля.
- Сетевые контракты поставщиков проверены через HTTPX MockTransport. Live-TMDB требует ключ, а live-AniList — подтверждённое право использования. Оба каталога выключены по умолчанию.
- Срок действия обновления медиаданных зависит от успешного ответа провайдера. Обновление запускается пользователем. Отдельной фоновой синхронизации и офлайн-редактирования нет.
- Проверка доступности покрывает выбранные экраны и правила axe. Установка на iOS и активация обновления Service Worker на реальных устройствах отдельно не проверялись.
- Строгий JSON-импорт отклоняет исторические строки с недопустимыми полями. Alembic оставляет исходные значения в базе. Полный дамп остаётся способом восстановления такой базы, а исправленные копии JSON можно импортировать обычным способом.
- Резервные копии перед операциями хранятся в той же базе. При больших объёмах учитывайте рост таблицы резервных копий и лимиты восстановления JSON. Расписания внешних дампов принадлежат обслуживанию deployment.
- CI описан в репозитории. Результаты здесь относятся к локально выполненным командам.

## 5. Обновление deployment

Репетиция на отдельной базе, остановка старых записывающих процессов, финальный дамп, ротация старого ключа, `alembic upgrade head`, запуск `app.main:app`, проверка входа, исходной коллекции и экспорта. Для возврата используйте проверенный дамп в отдельной базе. Полные команды и переменные приведены в [руководстве по развёртыванию](../README.md#развёртывание-и-обновление-render--neon).

Следующие шаги — прогнать cutover на копии фактических данных Neon, проверить установку PWA на целевых устройствах и выполнить live-проверки разрешённых каталогов. Для регулярной эксплуатации полезны внешний зашифрованный резервный архив и периодическая проверка восстановления.
