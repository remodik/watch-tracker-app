# Архив просмотренного — теперь с настоящим бэкендом

Тот же дизайн и функционал, что и раньше, но данные хранятся не в `localStorage`
браузера, а в базе данных на сервере (SQLite локально для разработки, Postgres
на проде). Фронтенд обращается к API вместо чтения/записи локального хранилища.

## Структура

```
main.py            — FastAPI-приложение: API + отдача статики
static/index.html  — фронтенд (тот же дизайн, что и watch-tracker.html)
import_data.py      — разовый скрипт импорта watchlist.json в базу
requirements.txt
Procfile            — команда запуска для Railway
```

## Локальный запуск (для проверки)

```bash
pip install -r requirements.txt --break-system-packages   # или через venv
python3 -m uvicorn main:app --reload
```

Откроется на http://127.0.0.1:8000 — база по умолчанию `watchlist.db` (SQLite,
файл рядом с main.py). Один раз перенеси свою текущую коллекцию:

```bash
python3 import_data.py watchlist.json
```

## Деплой на Railway + Neon (Postgres)

1. **База данных (Neon):**
   - Создай проект на neon.tech (бесплатный тариф).
   - Скопируй connection string вида
     `postgresql://user:password@ep-xxx.neon.tech/dbname?sslmode=require`.

2. **Railway:**
   - Создай новый проект → Deploy from GitHub repo (залей эту папку в отдельный
     репозиторий) либо `railway up` из CLI прямо из этой директории.
   - В Variables добавь:
     - `DATABASE_URL` — строка подключения из Neon.
     - `APP_TOKEN` — любой свой секретный токен (придумай длинную случайную
       строку). Он защищает API от посторонних, так как сайт будет публично
       доступен по ссылке. Без него любой, кто узнает URL, сможет редактировать
       коллекцию.
   - Railway сам подхватит `Procfile` и задеплоит.

3. **Перенос коллекции в облачную базу** (один раз, с своего компьютера):

   ```bash
   DATABASE_URL="postgresql://user:password@ep-xxx.neon.tech/dbname?sslmode=require" \
     python3 import_data.py watchlist.json
   ```

   (перед этим `pip install -r requirements.txt --break-system-packages` локально,
   если ещё не ставил)

4. Открой сайт по выданному Railway URL. При первом заходе он спросит токен —
   введи тот, что задал в `APP_TOKEN`. Токен сохраняется в `localStorage` этого
   браузера, повторно спрашивать не будет (пока не удалишь данные сайта или не
   зайдёшь с другого устройства/браузера — там спросит снова).

## Почему это решает проблему с пропажей данных

`localStorage` — это хранилище браузера, а не сервера: браузер может почистить
его при очистке кэша/данных сайтов, при нехватке места на диске, в приватном
режиме, при смене профиля и т.д. Экспортированный JSON-файл не страдает от
этого, поэтому и не пропадал — а вот автосохранения в localStorage были
уязвимы. Теперь все данные лежат в Postgres на Neon — это внешняя база,
независимая от твоего браузера и компьютера, с собственными бэкапами.

## Импорт/экспорт в самом сайте

Кнопки «Экспорт JSON» / «Импорт JSON» остались — можно так же выгружать бэкап
одним файлом или объединять/заменять коллекцию с уже существующего JSON.
