# Watch Tracker

Однопользовательская медиатека для аниме и фильмов. Ведите список просмотров, отмечайте сезоны и эпизоды, ставьте оценки, сохраняйте заметки и возвращайтесь к истории в годовом отчёте.

- Обзор, коллекция, избранное, календарь релизов, статистика и настройки.
- Постеры, компактный список и таблица. Поиск по названиям, жанрам и заметкам, фильтры в URL и постраничная выдача.
- Ручное добавление и опциональный поиск в AniList и TMDB. Пользовательские заметки, оценки и просмотренный прогресс сохраняются при обновлении метаданных.
- Импорт JSON с предпросмотром, экспорт, автоматические резервные копии перед изменениями с потерей данных и восстановление.
- Устанавливаемая PWA. Статические ресурсы кэшируются. Для доступа к коллекции и записи изменений требуется подключение.

## Локальный запуск

Требуется Python 3.12. Node.js нужен для проверок фронтенда и Playwright. Приложение использует готовые локальные ресурсы и не требует сборки JavaScript для запуска.

```sh
python -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
python -c 'import secrets; print(secrets.token_urlsafe(32))'
```

Сохраните сгенерированное значение в `APP_TOKEN` в `.env`, затем выполните:

```sh
alembic upgrade head
uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload --no-access-log
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000) и введите ключ доступа. Если используете другой адрес или порт, укажите соответствующий `APP_ORIGIN`. SQLite по умолчанию хранит данные в `watchlist.db` в рабочем каталоге.

| Переменная | Назначение |
| --- | --- |
| `APP_ENV` | `local` для локального HTTP или `production` для HTTPS. По умолчанию `production`. |
| `APP_TOKEN` | Общий секрет входа. Обязателен при включённой авторизации. В production минимум 32 символа. Пробелы сохраняются буквально, управляющие символы запрещены. Ротация отзывает ранее выданные сессии. |
| `APP_DISABLE_AUTH` | Значение `1` разрешено в `APP_ENV=local`. Используйте этот режим на loopback-интерфейсе. |
| `APP_ORIGIN` | Внешний origin со схемой и, при необходимости, портом. Укажите точный HTTPS-origin в production. |
| `DATABASE_URL` | SQLAlchemy URL для SQLite или PostgreSQL. В production укажите постоянную базу PostgreSQL. |
| `DATABASE_URL_DIRECT` | Необязательное прямое подключение к той же базе для Alembic, если приложение использует пулер Neon. |
| `ANILIST_ENABLED` | `1` включает AniList после проверки применимых условий и разрешения. |
| `TMDB_READ_TOKEN` | API Read Access Token TMDB. Пустое значение отключает интеграцию. |
| `BACKUP_RETENTION_DAYS`, `BACKUP_MAX_AUTOMATIC_COUNT` | 30 дней и 20 автоматических копий по умолчанию. Самая свежая защищена от автоматического удаления. |
| `PORT` | Порт, предоставляемый Render. Контейнер по умолчанию слушает 8000. |

API использует отзываемые сессии в базе с cookies `HttpOnly` и `SameSite=Strict`. В production cookies помечаются как `Secure`. Изменяющие запросы требуют CSRF-токен. Ограничение ошибок входа действует по IP и на приложение в целом, сохраняется в БД и разделяется между экземплярами. В интерфейсе можно выйти с одного устройства или завершить все сессии.

## Каталоги и время просмотра

- **Шикимори.** Поиск аниме по русским и оригинальным названиям. Включается через `SHIKIMORI_ENABLED=1` и использует публичный API. [Шикимори API](https://shikimori.io/api/doc)
- **Где смотреть.** Предложения по стране на основе JustWatch через TMDB. Используется существующий токен TMDB. [Настройка](docs/deployment.md#шикимори-и-доступность-релизов)
- **AniList.** Для чтения публичных метаданных ключ не требуется. Включение зависит от применимых условий. Они ограничивают использование API в конкурирующих трекерах и массовое накопление данных. Адаптер запрашивает выбранные произведения, сохраняет связи между записанными в каталоге тайтлами и возвращает подтверждённое расписание. Записи продолжений остаются самостоятельными. [Условия AniList](https://docs.anilist.co/guide/terms-of-use) · [Лимиты AniList](https://docs.anilist.co/guide/rate-limiting)
- **TMDB.** В аккаунте TMDB откройте API Settings и скопируйте **API Read Access Token** в серверную переменную `TMDB_READ_TOKEN`. Адаптер ищет фильмы с локалью `ru-RU` и подбирает размеры постеров через конфигурацию провайдера. Указание источника и логотип размещены в настройках. [Документация и атрибуция TMDB](https://developer.themoviedb.org/docs/faq) · [Изображения TMDB](https://developer.themoviedb.org/docs/image-basics)
- Обновление сведений доступно на странице произведения. Кнопки в настройках обновляют до шести связанных записей за вызов, начиная с самых давних. На странице календаря можно обновить ближайшие релизы. Время показа календаря следует часовому поясу браузера.
- Время просмотра оценивается по длительности фильма или эпизода и известному прогрессу. Указано покрытие по длительности. Месячные просмотры и годовой отчёт берутся из зафиксированной истории, активность добавления отображается отдельно. Записи прежней коллекции мигрируют без искусственной истории.

## Развёртывание и обновление Render + Neon

Для существующего Web Service на Render сохраните подключение к репозиторию и проверьте его настройки перед обновлением. Для Python runtime укажите Build Command `pip install -r requirements.txt` и Start Command `uvicorn app.main:app --host 0.0.0.0 --port $PORT --no-access-log`. Настройте health check `/api/health`. При использовании Docker Render запускает команду из `Dockerfile`. На платных сервисах доступна команда pre-deploy `alembic upgrade head`. На бесплатном тарифе примените миграцию вручную к нужной базе перед запуском новой версии. Не запускайте миграцию на этапе сборки. [FastAPI на Render](https://render.com/docs/deploy-fastapi) · [Этапы развёртывания Render](https://render.com/docs/deploys)

Для совместимости с прежней командой сохранён alias `main:app`. Файл `railway.toml` поддерживает альтернативное развёртывание на Railway.
1. В Neon получите строку подключения к существующей базе. Для миграций и дампа используйте прямой адрес с параметрами TLS, выданными Neon. Если строка `DATABASE_URL` использует пулер, укажите URL без `-pooler` в `DATABASE_URL_DIRECT` для той же базы, роли и ветки. [Подключение Neon](https://neon.com/docs/get-started/connect-neon) · [Пулер Neon](https://neon.com/docs/connect/connection-pooling)
2. Снимите дамп PostgreSQL и восстановите его в тестовую базу или проверьте миграции на отдельной ветке Neon. На копии выполните `python -m app.preflight --dry-run`, `alembic upgrade head` и `alembic check`. Сверьте количество записей, старые идентификаторы, даты добавления, заметки и сезоны. Проверьте вход, экспорт и импорт. [Ветвление Neon](https://neon.com/docs/introduction/branching)
3. Назначьте окно обслуживания. На время дампа и переключения остановите старое приложение и другие процессы, которые пишут в эту базу: старый код не заполняет новые индексы и не ведёт историю. После остановки сделайте финальный дамп. Проверьте, что переменные указывают на исходную базу, а `APP_ENV=production` и `APP_ORIGIN` соответствуют HTTPS-домену. Задайте новый случайный `APP_TOKEN`: прежняя версия хранила ключ в браузере.
4. Примените миграции через Render pre-deploy на платном сервисе или однократно вручную из каталога этой версии с прямым подключением к базе. Запустите сервис, проверьте `/api/health`, вход, исходную коллекцию и возможность скачать архив. Приложение проверяет применённую ревизию при запуске.
5. Для отката остановите запись и сохраните свежий дамп изменённой базы. Проверьте восстановление предмиграционного снимка в отдельную базу, затем подключите подходящую версию приложения к проверенной базе. Историю и изменения, сделанные после обновления, сохраните отдельным экспортом или дампом.

Миграция `0001_legacy` распознаёт фактическую исходную таблицу `items` и использует её как baseline. `0002_library` добавляет индексы, новые колонки, журнал, таблицы сессий и резервных копий. Колонки прежней версии и сохранённые значения остаются в базе. Совпадения, уже присутствовавшие в старых данных, сохраняются за всеми исходными ID. Для SQLite временную копию делайте через SQLite Backup API или при остановленном приложении. Запускайте миграции против копии через `DATABASE_URL=sqlite:///./migration-copy.db alembic upgrade head`.

## Резервное копирование и восстановление

**Коллекция.** В настройках можно скачать `watchlist.json` версии 2 с ID, датами, данными произведений и событиями просмотра. Восстановление принимает старый массив JSON (v1) и архив v2. При импорте сначала посмотрите количество новых строк, совпадений и ошибок. Режимы — объединить, обновить совпадения, заменить всю коллекцию. Замена требует отдельного подтверждения. Сервер сохраняет снимок перед заменой, удалением и обновлением совпадений в той же транзакции. Снимки доступны для скачивания и восстановления.

```sh
python import_data.py watchlist.json --preview
python import_data.py watchlist.json --mode merge
```

Импорт ограничен 16 МиБ тела запроса, 10 000 записей и 50 000 событий. У исторических строк с некорректными типами, статусами, датами или прогрессом исходные значения сохраняются в базе. Если строгая валидация выдаст ошибки, исправьте их в копии JSON перед импортом или восстановите исходную базу из её дампа.

**Полная база.** Снимки из приложения хранятся в той же базе. Для независимого восстановления регулярно сохраняйте дампы PostgreSQL в закрытое внешнее хранилище. Ограничьте доступ к ним: в архиве содержатся заметки и история просмотра. Для периодического копирования запускайте команду `pg_dump` по расписанию на доверенной машине c секретом `NEON_DIRECT_URL` и выбранным сроком хранения. Копии можно удалить в настройках. Ручные копии исключены из автоматического удаления.

```sh
PGDATABASE="$NEON_DIRECT_URL" pg_dump --format=custom --file watch-tracker.dump
PGDATABASE="$RESTORE_DATABASE_URL" pg_restore --exit-on-error --no-owner --no-privileges watch-tracker.dump
```

Вторая команда предназначена для пустой тестовой базы. Для SQLite сохраните полный файл через `sqlite3 watchlist.db ".backup 'watch-tracker.sqlite3'"`, восстановите под новым именем и проверьте `PRAGMA integrity_check;` до переключения приложения. [Документация Neon по дампам](https://neon.com/docs/manage/backup-pg-dump)

## Архитектура и проверки

- `app/` — FastAPI, конфигурация, сессии, модели SQLAlchemy 2, схемы Pydantic 2 и маршруты.
- `app/services/` — идентификация произведений, прогресс, импорт, аналитика и вызовы каталогов через HTTPX.
- `migrations/` — ревизии Alembic для SQLite и PostgreSQL.
- `static/` — ES Modules, CSS, локальные Manrope и Onest, Lucide, Chart.js, Web App Manifest и Service Worker.
- `tests/` — API, миграции, тесты каталогов с HTTPX MockTransport и сценарии Chromium через Playwright. CI использует изолированный PostgreSQL 16.

```sh
pip install -r requirements-dev.txt
ruff check .
ruff format --check .
pytest -q
# Укажите URL отдельного тестового PostgreSQL с правом CREATE DATABASE, например:
TEST_POSTGRES_URL=postgresql://postgres:watch_ci@127.0.0.1:5432/postgres pytest -q
npm ci
npx playwright install chromium
npm run check
WATCH_TEST_PYTHON="$VIRTUAL_ENV/bin/python" npm test
```

Миграционный тест поднимает историческую схему из исходного коммита, поэтому для тестов нужен полный Git checkout. Зафиксированные версии JS-зависимостей и лицензии размещены в `package-lock.json` и `static/vendor/`. Версии ресурсов PWA вычисляются автоматически из содержимого файлов. Пользователь может активировать обновление после завершения текущего действия.
